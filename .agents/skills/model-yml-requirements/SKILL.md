# Every model and source needs a companion .yml file

No model or source is complete without a `.yml` file declaring it — undocumented, untested models are not acceptable.

## Rules

- Every folder of models has a `.yml` file (e.g. `_staging__models.yml`, `_marts__models.yml`) that documents **every** model in that folder — new models must be added to the existing file, not left undeclared.
- Every source system has its own `.yml` under `models/staging/<source>/` (e.g. `_salesforce__sources.yml`) declaring the `sources:` block — required before any model can `{{ source(...) }}` from it. See [[source-and-ref-usage]].
- Minimum required per model entry:
  - `description` — plain-language purpose of the model, not a restatement of the name.
  - Primary key column(s) with a `unique` and `not_null` test (via `dbt_utils.unique_combination_of_columns` if composite).
  - Every foreign key (`_id`-suffixed) column has a `relationships` test back to its parent model.
  - Column-level `description` on any non-obvious column (calculated fields, flags, anything not self-evident from the name).
- Sources additionally declare `loaded_at_field` and a `freshness:` block where the source has a reliable load timestamp.
- If a model was generated by `nyl_dbt_utils.generate_quarantine_models`, still add a `.yml` entry for all three generated models (`__flagged`, base, `__quarantine`) — the generator does not write yml for you.

## When adding or reviewing a model

1. Check whether a `.yml` file already exists for the model's folder.
   - **If it exists**, add the new model's entry to it — never leave a model undeclared in an existing file.
   - **If it does not exist**, create one immediately using the naming pattern already used in that project (e.g. `_staging__models.yml`, `_marts__models.yml`), scaffolded with at minimum:
     ```yaml
     version: 2

     models:
       - name: <model_name>
         description: "<TODO: describe what this model represents>"
         columns:
           - name: <primary_key_column>
             description: "<TODO>"
             tests:
               - unique
               - not_null
     ```
     Do not leave placeholder `description` fields as `<TODO>` — fill them in with the model's actual purpose before finishing.
2. Confirm the new model's entry has a real `description`, primary-key tests, and FK `relationships` tests (not the placeholder scaffold).
3. Confirm any new `source()` call has a corresponding `sources:` declaration in a `.yml` file — if that file doesn't exist either, create it the same way, following the pattern:
   ```yaml
   version: 2

   sources:
     - name: <source_name>
       tables:
         - name: <table_name>
   ```
